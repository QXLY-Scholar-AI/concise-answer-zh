# concise-answer-zh · 简明中文写作

让AI的中文回答更清楚、更好读，也更容易使用。

这套Skill借鉴ASD-STE100 Issue 9的技术写作原则，将选词、主体、条件、步骤和段落组织整理为可执行的中文规范。它适合起草和修改解释、文章、报告及操作说明，也可以在较长回复发出前检查表达。

**目标是提高可读性。** 必要时补充主体、条件或例子；重复、离题或绕口的内容则重新整理。全文需要多长，由任务决定，不设统一压缩比例。

## 它会处理什么

| 常见问题 | 处理方式 |
| --- | --- |
| 不清楚谁负责哪项动作 | 写明材料中已有的主体、对象和职责 |
| 操作写在前面，适用条件藏在后面 | 把必须预先知道的条件放到对应动作之前 |
| 同一个对象换了多个名称 | 统一术语，保留首次出现的全称与缩写说明 |
| 短句很多，前后却接不上 | 按信息关系组织自然段，保留必要的连接表达 |
| 重复总结，关键解释反而难找 | 删去无信息的重复，保留定义、数据、公式与复算步骤 |

| 1.7 | 词语 | 技术名词不自动获准作动词；同时符合技术动词类别时另判 | 明确动作；不将英文限制误用为全面禁止中文词类活用 | 55 |

| 1.11 | 词语 | 同一对象不轮换不同技术名词 | 术语一致；已明确定义的全称与短称可对应使用 | 57 |

| 1.13 | 词语 | 技术动词不自动获准作名词；过去分词作修饰等例外另判 | 区分过程名称与动作表达，不生搬英文许可 | 60—61 |

| 2.2 | 多词名词 | 正式长技术名词首次写全；明确短称或正确连字符关系；避免缩写过密 | 建立全称与短称，正式名称不硬拆；不套英文计词规则 | 64—66 |
| 3.1 | 动词 | 用词典列出的批准动词形式；技术动词另按1.12判断 | 不将英文词形表变成中文限制 | 67—68 |
| 3.2 | 动词 | 规定可用时态、祈使、不定式和作形容词的过去分词 | 中文保留时间与状态，降低结构复杂性 | 68 |
| 3.3 | 动词 | 过去分词可表示状态，不能一概认作被动动作 | 区分状态描述和行为发生 | 68—69 |
| 3.4 | 动词 | 避免助动词构成复杂结构；非禁止全部情态或将来表达 | 动作直接，保留能力、必要性及时间含义 | 69 |
| 3.5 | 动词 | -ing形式原则上只作技术名词或其修饰，少量批准词另有许可 | 英语限制不迁移；处理中文长修饰和动作链 | 70—71 |
| 3.6 | 动词 | 优先主动；描述中施事未知允许被动；状态表达另判 | 明确已知主体，不为主动句补造原因或执行者 | 71—74 |
| 3.7 | 动词 | 有适用批准动词时，直接表达动作而非用名词绕述 | 减少无功能的名词化套层，必要概念名词保留 | 75 |

| 4.2 | 句子 | 不为变短而省掉必要名词、动作、主语等成分或用英语缩合形式 | 保留必要成分、条件与否定范围，允许无歧义的自然中文省略 | 79 |
| 4.3 | 句子 | 复杂并列内容可列项；引导语、层级、否定与对象关系明确 | 列表用于真正并列或步骤，不把全部解释变清单 | 80—82 |
| 4.4 | 句子 | 用适当连接表达联结相关句子 | 保留转折、条件、时间和因果；不能虚加关系 | 83 |
| 4.5 | 句子 | 适用时用冠词或指示词，存在泛指和正式标识等例外 | 中文不机械补“该、此、一个”；检查指代与修饰范围 | 84—85 |
| 5.1 | 程序写作 | 程序句最多20个英文词；程序注释按描述规则处理 | 降低单句负担，不改成20个汉字上限 | 87—88 |
| 5.2 | 程序写作 | 每句一项指令，同时动作除外；一个步骤可有多句 | 按行动关系分步，结果和关键检查紧跟动作 | 88—89 |
| 5.3 | 程序写作 | 操作指令用祈使式，必要强制性或条件不能丢失 | 直接说明做什么，明确必要性与责任 | 89—90 |
| 5.4 | 程序写作 | 必须预先知道的条件先交代，再给指令 | 条件前置，核对修饰范围，不强行前置全部细节 | 90 |
| 5.5 | 程序写作 | 注释仅提供信息；指令、限值、结果和安全内容放适当步骤 | 遮住注释仍应能正确执行；移动关键内容，不删掉它 | 91—93 |
| 6.1 | 描述写作 | 逐步提供信息，每句围绕一个主题 | 先给理解后文所需的信息，再展开细节 | 95—96 |
| 6.2 | 描述写作 | 关键词、关键短语和连接表达建立逻辑结构 | 保留承担追踪和连接作用的重复，避免任意换词 | 96—98 |
| 6.3 | 描述写作 | 描述句最多25个英文词；拆句仍保留信息 | 按语义拆复杂句，不设25个汉字上限 | 98 |
| 6.4 | 描述写作 | 用段落组织相关信息，主题句与后句配合 | 连贯自然段，避免一句一段的碎片化写法 | 99 |
| 6.5 | 描述写作 | 每段一个中心；主题句与前文联系 | 段内补充解释同一中心，主题转换另起段 | 100 |
| 6.6 | 描述写作 | 每段不超过六句 | 按中心与阅读负担拆段，不机械套句数 | 101 |
| 7.1 | 安全指令 | 用适用词或符号标风险等级，行业可有不同体系 | 遵守任务所在领域的等级规范，不凭空增加风险提醒 | 103—104 |
| 7.2 | 安全指令 | 安全指令以明确防范动作或预先条件开头 | 条件和动作具体，不用空泛口号代替 | 105 |
| 7.3 | 安全指令 | 有依据时说明风险或可能后果 | 必要后果保留，维持不确定性，不编造 | 106 |
| 8.1 | 标点与计词 | 英语STE不用分号，其他一般标点遵循适用资料 | 中文按句间关系和目标格式用标点，不自动禁分号 | 107—108 |
| 8.2 | 标点与计词 | 连字符连接实际相关词，不等于破折号 | 不创造含糊中文复合词，必要关系写明 | 108 |
| 8.3 | 标点与计词 | 括号可用于引用、标识、步骤号、缩写、单复数、解释与选项 | 保留必要编号与条件，不将括注一概删除 | 109—110 |
| 8.4 | 标点与计词 | 竖排列表的冒号结束引导语计词，各项独立计词 | 英文计词不迁移；引导语和各项分别保持易读 | 110 |
| 8.5 | 标点与计词 | 括号在外句算一词，内部仍独立检查句长 | 不用括号掩藏复杂解释 | 111 |
| 8.6 | 标点与计词 | 七类元素有特定计词口径，详见下表 | 数据、单位、公式、引用和专名不可因精简改变 | 111—114 |
| 8.7 | 标点与计词 | 正确连字符词整体算一词 | 不为降低统计字数任意拼接词 | 114 |
| 9.1 | 写作实践 | 逐词替换不能保持意义或通顺时，重组句子；修改后检查全文影响 | 先理解再重写；可删重复，缺失技术事实须核实 | 115—119 |
| 9.2 | 写作实践 | 用词符合批准意义和词性，少量词存在多个许可 | 中文按实际语境和词义判断，不照搬英文白名单 | 119—121 |
| 9.3 | 写作实践 | 组合后形成的新短语动词须另有许可，不能只逐词判断 | 检查组合后的真正含义，避免字面近似误义 | 121—122 |
| 9.4 | 写作实践 | 同一语境、同一动作或对象保持一致措辞 | 同义步骤统一表达，不为了避免重复任意改名 | 122—123 |

## 安装

### 交给AI安装

下载项目压缩包，或将本目录打包后，交给支持安装本地Skill的AI工具：

> 请从这个压缩包安装concise-answer-zh，并保留其中的自动调用设置。

安装完成后，让AI确认已识别到concise-answer-zh，并用下面的示例试一次。不同工具对安装目录、压缩包导入及自动调用的支持有所不同，按所用工具的Skill安装方式操作即可。

### 手动安装

将整个`concise-answer-zh`文件夹放入所用工具支持的技能目录中，确保工具能够找到`concise-answer-zh/SKILL.md`，并保留`references/`和`agents/`目录。若工具要求刷新技能列表或重启会话，完成后再调用。

如果工具暂不支持Skill，也可以提供[中文写作规范](references/中文写作规范.md)，让AI按其中的要求处理稿件。

## 调用示例

### 修改已有稿件

> 请用concise-answer-zh整理下面这段说明，面向第一次接触这个主题的研究生，直接给我修改后的全文。

接着附上待修改的文字。

### 起草一份说明

> 请使用concise-answer-zh，根据所附材料写一份给新同事看的操作说明，让他知道每一步由谁完成、需要什么条件、怎样检查结果。

### 保留详细推导

> 请使用concise-answer-zh解释下面的方法，保留公式、变量定义和逐步代入过程，让我能自己复算。

### 查看修改理由

> 请用concise-answer-zh修改这份稿件，并在成稿后简要解释三处最影响理解的修改。

默认只输出任务所需的成稿；需要修改说明时，可以像上面一样明确提出。

## 自动使用

Skill入口允许AI在适合的写作任务中自行使用。`agents/openai.yaml`中也设置了`allow_implicit_invocation: true`，供识别该配置的工具使用。

在支持自动选择Skill的工具里，AI可以在准备较长的中文解释、报告或操作说明时，判断是否需要整理表达。你也可以直接告诉它：

> 写较长的中文说明或稿件时，请按concise-answer-zh整理表达，保留我要求的完整内容。

自动选择由所在工具和模型决定；明确点名调用可以直接表明本次任务需要使用这套规范。它随写作任务工作，不会自行启动定时任务或独立后台服务。

## 一个简短例子

以下为教学改写示例。

**修改前：**

> 每天提交各商品销量，再按前一补货周期的实际销量补货。库存水平也要确定，经销商不能自己决定订货量。

**修改后：**

> 经销商每天向GL提交各商品销量。每个补货周期开始时，分仓按经销商上一周期的实际销量补货。GL确定库存水平，经销商不能自行决定订货量。

修改后补出了材料中已有的执行者，读者能分清经销商、分仓和GL的职责。文字有所增加，但业务关系更明确，日常报告与周期补货也得到了区分。

## 规范来源

本项目依据ASD-STE100 Issue 9的9节、53条写作规则及词典使用方法，整理中文写作要求。英文专用的句长、词形等限制保留为参考，中文按信息关系和阅读负担组织表达。

这是中文写作的迁移设计。包内同时提供规则整理、中文执行说明、官方完整PDF和逐页检索文本。日常写稿使用中文规范；需要核查英文规则、例外、词典或原例时，再查对应原页。

## 判断有没有改好

读完修改稿，检查读者是否更容易理解对象和条件、追踪句段关系，以及完成所需的判断或操作。同时核对原有数据、公式、否定、适用范围和必要步骤是否完整。

文字需要展开时充分展开，已经说清楚的内容保持原样。最终交付的是一份更容易理解和使用的回答。
